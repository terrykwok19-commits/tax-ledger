## 税金台账：项目行可增减（架构级重构，已完成上线）

用户要求「项目可手动增减，但计算逻辑不变」。把 GRID 硬编码彻底换成**行模型**。

### 数据模型（S.rows 只存可变行）
三类 kind：`income`（收入项，带 rate）、`vatRate`（按增值税×费率，带 rate+half）、`input`（手工金额）。
固定行在 `FIXED` 常量里：income(sumIncome)/output/inputTax/vat/total，**不存进 S.rows**，由 `rowsOf()` 按「收入项 → 收入合计 → 销项税 → 进项税 → 增值税 → 附加 → 手工税费 → 税金合计」的顺序组装，顺序天然正确。

- 月份数据仍用 `m[行id]`；双态行手改值存 `m[行id + "Override"]`（`OV = id => id+"Override"`）
- `blank = () => ({})`：空对象，缺字段即 0/空，新增行不需要迁移月份数据
- 默认行 id 沿用旧字段名（goods/unbilled/service/city/edu/localEdu/stamp/incomeTax），**旧存档零成本兼容**
- `migrateRows(s, def)`：新版走规范化；旧版把 `s.rates` 灌到对应行、`s.taxes` 转 input 行、`showStamp/showIncomeTax === false` 直接删行

### 关键函数
- `calcMonth`：收入合计 = Σincome；销项 = Σ(income×rate)；增值税 = 销项−进项；base = max(vat,0)；附加 = base×rate×减半；total = base + Σ附加 + Σinput。返回 `vals/auto/manual` 三个字典，任意行统一用 `c.vals[id]` 取
- `isBlank`：遍历 S.rows，vatRate 查 OV 字段，其余查裸字段
- 渲染/累计/合计/导出/导入全部改为遍历 `rowsOf()`，用 `isEdit(r)` / `isHyb(r)` 分支，不再有任何硬编码字段名
- `addRow(kind)` / `renRow` / `editRate` / `delRow`：三个按钮「＋收入」「＋附加」「＋税费」；双击行标题改名；点百分比徽标改税率；✕ 删除（有数据二次确认）

### 导入（applyMatrix 重写为四遍）
① 按首列名称收数（名称即行的身份，与列位置无关）→ ② 名称对到行，表里有本地没有的行**自动建出来**（先查 DEF_ROWS 同名，再按「含税/金/费」建 input 行）→ ③ 写数，双态行先落 OV → ④ 与自动值比对，差 ≤0.005 则不标手改。返回 `{manCount, newTax}`
