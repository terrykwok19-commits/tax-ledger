
## 10:20–11:00 收入税费表迁到 D 盘项目族，接入亿企赢一键取数

- 用户要求：税金台账改成"浏览器里直接跑 + 自动从亿企赢科目余额表取数"，路径 `D:/onedrive/Work/金哪达/自动入账模板/收入税费表`；按台账公司绑 cid 后台取数（不跟随当前打开的账套）；单月或年月区间；继续部署 GitHub。
- **关键实测（决定架构）**：余额表接口 `financeweb/finance/accountBalanceSheet/query` 不认 cid —— `companyId`/`company-id`/`selectedCompanyId`/`X-Company-Id` 放 header 或 payload 六种写法全返回同一账套（181 行一致）。账套绑在登录会话上，只能走「进账套」。**所以书签脚本方案不可行，必须本地服务**。
- 另测：`file://` 页面 fetch `127.0.0.1` 可用（CORS *）；HTTPS 页面（GitHub Pages）被混合内容拦 → 在线版只能手动导入。
- 交付：`启动.bat`（GBK 编码，UTF-8 会被 cmd 解析错乱）+ `server.py`（ThreadingHTTPServer，静态托管 + /api/fetch，全局锁，跨年/格式/未绑定公司都显式报错）+ `index.html` 加「亿企赢取数」面板。
- 取数复用 `../账务复核/codes/src` 的 `open_finance_page` + `fetch_balance` + `verify`，不拷贝代码；profile 共用 `.pw_profile_<cid>`，同账套不能并发。
- 前端把接口行转成「科目余额表」矩阵喂给既有 `planBalance`，预览/项目同步/撤销零改动。**矩阵表头必须两层：第一层含「科目编码/科目名称」，第二层「借方/贷方」**，否则 `balCols` 判不出两层，全部取不到数（第一版踩过）。
- 实测：贸易 2026-08~10 一次取数 18.6 秒（166/173/177 行），3 个月 34 项，写入 10/13/11 项，撤销全还原；与手工导出余额表金额一致（10 月 500104=2,708,520.22）。
