### 11:30 导入 Excel 缺行问题（粤书亚「出口免税」）

- 现象：粤书亚台账里「出口免税」在导入后没建行 / 被当成税金算进税金合计。
- 根因两条：
  1) 旧逻辑 `isFee = /税|金|费|附加|基金/`，「出口免税」含「税」⇒ 被建成**手工税费**，
     金额进「税金合计」（原文件 10 月税金合计 496,255.44 里含 481,674.72 的出口免税，明显错）。
  2) 只有「有数值」的行才进 `picked`，全空的项目行永远不会被建出来。
  3) 同名项目在收入区和税费区各出现一次时只认一个，收入侧那行就丢了。
- 改法（applyMatrix）：
  - 新增分节跟踪 `SECTION_RE` / `sectionOf()`：一、基础经营数据→income，二、增值税→vat，其余→fee；
    分节标题行直接 continue。
  - `isExempt = /免税|不征税|出口/` → 判为**收入项、税率 0**（收入合计含、销项税不含、税金合计不含）。
  - 空行也进 `picked`（vals={}），因此表里有的项目一律建行；`secOf` 记首次出现分节，
    任一次出现在收入区即认定为收入项。
  - 已有同名行但是 kind=input/vatRate 且应为收入项 → 就地转 kind=income，OV 值迁回普通键，
    并提示「「出口免税」按收入项处理（税率 0）」（`converted` + impMsg）。
  - 跳过规则补 `/^(备注|说明|注[:：]|合计|小计|总计|累计)/`。
- 实测（用桌面真实文件 粤书亚_税金台账_2026.xlsx 走真实导入通道）：
  - 新增 5 行（出口免税、租金、房产增值税、房产城建税、房产税），出口免税落在收入合计上方、rate=0；

  - 导出 xlsx：明细台账第 7 行、税负率第 6 行都有出口免税，金额 481,674.72；
  - 预置「已存在同名税费行」场景再导入 → 就地转收入项，无重复行，金额保留。

### 17:10 修「城建税没减预缴」——抵减逻辑原来是靠城建税行的 kind 撑着的

- 病因两处：`isCityRow` 原来要求 `kind === "vatRate"`，城建税一旦被建成手工税费行（老台账/导入）就永不抵减；
  另外 hyb 行有手改值（`cityOverride`）时直接取手改值，把预缴抵消掉了 —— 用户在格子里照着毛额敲一遍就复现。
- 修法：
  * `isCityRow` 放宽为「非 income / 非 preCity 且 id=city 或名字含 城建税|城市维护建设税」；
  * `calcMonth` vatRate 分支：手改值 ≈ autoRaw（毛额）时仍减预缴，其它手改值当净额；
  * input 分支：城建税手工行也减预缴，且只在 `has(m[r.id])` 时减，避免 -50 负数；
  * 新增 `normalizeCityOverride(m)`（paint 每帧调用）：手改值≈毛额就地删 override 回归自动值，
    解决「输入框 210、合计按 160」的显示打架；
  * `rangeSum` / 合计行 T / 导出 addRow / feeLine 四处对城建税改取 `c.vals`，累计与导出不再算毛额；
  * `defOrder`、导出 sheet1 在 input 类城建税行后也插「预缴房产城建税」；
  * `rateTag` 给 input 类城建税加「手工 · 已减预缴」，输入框 title 显示「手填 X − 预缴 Y = Z」。
- 实测（headless Edge）：A 默认 160；B 城建税改 input 填 210 → 160；C 手改 210 → 自动归一 160 且 override 被删；
  D 手改 160 → 160 保留手改；E 手改 200 → 200；F 无预缴 → 210；G 费率 5% → 100；合计均 6,310。
  导出 xlsx 两表城建税 160；导入真实结构（毛额 210 / 净额 160 两版）→ 0 新建、0 手改、160、合计 6,310。

### 17:20 税金合计加上预缴房产增值税
